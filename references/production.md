# 从内容到成品

## 背景提示词的构成

先看参考图，再描述要继承的视觉关系。下面是提示词结构，主题和主体应换成本次文章内容；括号不是需要出现在图中的文字。

```text
为 Ryan AI Radar 的文章生成黑白编辑摄影拼贴背景。
文章主题：[主题]。想表达的判断：[一句话]。视觉主体：[从文章提炼的对象和动作]。
参考附图的黑底留白、暖白纸张、摄影剪贴和克制印刷颗粒，不复制附图的人物、物件或文字。
超宽约 2.35:1 构图，左侧约 50–55% 留干净近黑色区域供后期排字；主体集中在右侧并留出完整轮廓。
用真实材质与明确轮廓建立辨识度。根据主体选择少量撕纸边、横向切片或白色细条，纹理限于图像区域。
主体应能另行取景为完整方图。没有文字、数字、品牌标识或水印。
避免彩色科技背景、机器人、大脑图标、发光数据流、光滑 CGI 和密集装饰。
只输出无字背景，不生成标题、不生成样机或方案对比页。
```

如用户指定白底、纯文字或其他明确方向，应按其要求调整，而不是让模板覆盖用户选择。工具调用遵循当前可用图像工具的要求；不要在技能里固定某个模型名。编辑既有背景前先查看原图。

参考图的用途是风格引导。涉及真实人物或文章里特定产品时，另用可靠来源的素材确保身份与外观，不用风格参考里的角色替代。

## 本地中文排版

使用 SVG、HTML/CSS 或当前可靠的图形排版工具，保留文字可编辑。图像生成阶段不写中文字。字体可用黑体/无衬线中文字体，例如本机的 Heiti SC、STHeiti 或 PingFang SC；其他环境选已安装的中文字体，不盲目沿用 macOS 字体路径。

下表是近期 900×383 成品的排版起点，不是不可调整的固定格子。

| 元素 | 参考值 |
| --- | --- |
| 背景 / 主文字 / 辅助字 | `#060606` / `#F4F3EE` / `#AAA9A5` |
| 左侧边距 | 约 50–60 px |
| 品牌行 | 顶部约 42–50 px，字号 11–13 px |
| 短横线 | x 约 52，y 约 76，宽 50，高 4–5 px |
| 两行标题 | 字号通常 44–54 px，行距约 60–70 px；长句重写或重新分行 |
| 辅助分隔线 | y 约 265–270，细线，长度随文案区调整 |
| 副标题 | 字号约 18–22 px，可省略 |
| 必要口径 / 品牌尾注 | 字号约 12–14 px，不能承载读者必须看到的全部限制条件 |

标题应保持一眼能读的节奏。不要为塞下长标题不断缩小字体；封面可以提炼短句，与正文标题含义一致即可。没有依据的时长、排名、金额和断言不能为构图需要而添加。

导出后实际查看，确认没有字体回退造成的空框、错字、重叠或边界截断。高分辨率导出只提高细节，不弥补布局错误。

## 方图的处理

优先从无字背景重新取景，保留完整主体。必要时用图像编辑重新安排对象，再本地加极短文案。右侧区域不够宽时不能把长方形主体硬拉成正方形。

如果选择共用一套构图，必须在设计时就让完整关键信息落在方形裁切范围；不能事后用“中央 70% 安全区”蒙混过关。900×383 的横图居中裁方形实际只保留 x 约 258.5–641.5。

把方图缩到 200×200 与 120×120 检查：先看能否辨认主体，再看是否需要文字。聊天卡片旁通常已经有文章标题，方图不需要重复完整标题。

## 打包脚本

`scripts/package_covers.py` 接受已经排好版的横图和已经重新取景的方图。它不会从横图自动猜一个方图，不访问网络，也不上传公众号。

默认输出：

- 横图 900×383 和 1800×766。
- 方图 800×800、200×200、120×120。
- 2680×800 上传母版，左横右方。
- `crop-fields.json` 与从母版按坐标回算的 `crop-check-wide.png` / `crop-check-square.png`。
- `cover-preview.png`，含横图和两档方图缩略预览。

可用 `--height` 调整母版高度，需为 20 的正整数倍，使 47:20 横图和 1:1 方图都落在整数像素上。脚本据输出尺寸生成字段。传入约 2.35:1 横图和严格正方形方图；错误比例会在写入前报错。

交付时另保留本次无字背景、可编辑排版文件与实际使用的生成提示词。参考成品只是说明材料，不应把旧文章标题直接用于新稿。
