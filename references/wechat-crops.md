# 双比例封面与微信后台核验

仅在准备上传、修改封面或排查转发裁切时读取。本技能不保存公众号凭据、素材 ID、草稿 ID 或固定出口 IP。

## 母版和坐标必须配套

默认母版为 2680×800：左侧 1880×800 是 2.35:1 横图，右侧 800×800 是独立方图。母版只是上传容器，不放进正文、不直接展示为横版成品。

每个裁切框字段按 `x1_y1_x2_y2` 表示，使用整张母版的归一化坐标。默认布局为：

```json
{
  "pic_crop_235_1": "0_0_0.701493_1",
  "pic_crop_1_1": "0.701493_0_1_1"
}
```

换母版布局或尺寸后，按真实像素边界重新计算 `x/W`、`y/H`，并回算像素框检查。不要把这组坐标用于单独的 900×383 横图。

## 保存与读回

用户授权保存草稿或更新指定封面后，再操作已有公众号上传工具。仅制作封面不包含这项外部操作授权。

1. 上传整张母版，取得它自己的封面素材 ID。
2. 把该 `thumb_media_id` 与这张母版的两项裁切字段放在同一篇文章的 payload 中。只修改用户指定的草稿或文章，不顺手更新其他稿件。
3. 读回已保存文章，确认素材 ID 正确。微信可能不原样返回 `pic_crop_235_1` / `pic_crop_1_1`，而是在 `cover_info.crop_percent_list` 中返回：

```json
{
  "cover_info": {
    "crop_percent_list": [
      {"ratio":"2.35_1","x1":"0","y1":"0","x2":"0.701493","y2":"1"},
      {"ratio":"1_1","x1":"0.701493","y1":"0","x2":"1","y2":"1"}
    ]
  }
}
```

按 `ratio` 查找、把坐标转成数值后比较；不要依赖数组顺序、数字的字符串格式，或误把顶层字段缺失当作未保存。本次 AI 付费文章于 2026-10-10 实际创建草稿并读回验证了上述结构；不是对未来接口行为的保证。

如果读回没有可用裁切信息，查看后台两个比例的实际预览。获得发送授权后才发送预览或真实转发用于验收。更新草稿不等于修复旧文章，已发出的聊天卡片是否刷新需要另行验证。

## 如实报告状态

| 已有证据 | 可报告 |
| --- | --- |
| 本地母版、回算坐标和缩略图检查通过 | 本地已适配 |
| 读回的素材 ID、两个比例坐标正确，或后台预览确认 | 后台已保存并核验 |
| 真实转发卡片显示完整 | 实际转发已验证 |

遇到 `40164`，展示接口本次返回的 IP，核对目标公众号并让用户处理白名单；不要复用历史任务的 IP。用户确认保存后可等 1–2 分钟重试一次；仍失败就记录阻塞，不持续盲重试。

如果创建草稿的请求结果不明，先查询是否已经创建，再决定是否重试，避免重复草稿。已取得草稿 ID 后用读回或指定更新操作继续；不要为核验重新创建。
